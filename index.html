AI WORKFLOW MAP

เข้าใจ ChatGPT, Work, Codex และ AI Agent ในหน้าเดียว — เลือกให้ถูก แล้วลงมือทำได้ทันที

1) เริ่มจากภาพใหญ่ก่อน

Model = สมอง

โมเดลคือความสามารถในการคิด เช่น GPT‑5.6 Sol, Terra, Luna และ GPT‑6 Astra

Chat / Work / Codex = วิธีใช้งาน

Chat คุยและคิด
Work ทำงานหลายขั้นจนเสร็จ
Codex งานโค้ด ระบบ และเทคนิค

AI Agent = ผู้ลงมือทำ

AI ที่รับเป้าหมาย วางขั้นตอน ใช้เครื่องมือ ทำหลายขั้น และส่งผลลัพธ์กลับมา

สรุป

Agent ไม่ใช่ชื่อโมเดล
Work คือ Agent สำหรับงานทั่วไปหลายขั้น
Codex คือ Agent สำหรับงานเทคนิค/ซอฟต์แวร์

2) เลือกโหมดให้ถูกก่อนเลือกโมเดล

ต้องการทำอะไรเลือกตัวอย่างระดับการคิด
ถาม คิด เขียน สรุป BrainstormChatContent, Strategy, Q&A, SearchInstant/Medium → งานทั่วไป
High/Extra High → งานซับซ้อน
อยากได้ “ชิ้นงานที่เสร็จ” หลายขั้นWorkResearch → วิเคราะห์ → ทำ Report / Sheet / Slide / SiteMedium/High เป็นหลัก
แตะ Code, Repo, Terminal, API, AutomationCodexสร้างเว็บ, แก้ระบบ, ทำ Script, Agent ทางเทคนิคHigh/Extra High เมื่องานยาก

จำง่าย: Chat = คุย / Work = ทำงาน / Codex = สร้างระบบ

4) ก่อนใช้ศัพท์เทคนิค: อะไร “ต้องมี” และอะไร “ยังไม่ต้องมี”

กฎสำคัญ: ถ้าทำ Content Agent, Slide Agent, Research Agent หรือผู้ช่วยงานใน ChatGPT ยังไม่ต้องสร้าง Repo และ Environment — ใช้ Project + Instructions + Files + Work ก็เริ่มได้แล้ว
คำนี้คืออะไรอธิบายแบบง่ายต้องใช้เมื่อไหร่ไม่ใช้ได้ไหม
Project ห้องงานของเรื่องหนึ่ง รวม Chat, Files, Instructions และ Context ไว้ด้วยกัน ทำงานต่อเนื่อง เช่น Content, Brand, Course, Client ได้ แต่ถ้างานยาว Project ช่วยไม่ให้ข้อมูลกระจัดกระจาย
Skill SOP หรือวิธีทำงานที่อยากให้ AI ทำซ้ำแบบเดิมทุกครั้ง งานที่มีขั้นตอนประจำ เช่น “คิด Hook → เขียน Script → QA” ได้ ช่วงทดลองใช้ Prompt ธรรมดาก่อนได้
Repo โฟลเดอร์โปรเจกต์ที่มีระบบจัด Version เช่น Git/GitHub — เป็น “ตัวงานจริง” ของเว็บ แอป หรือ Automation เมื่อ Codex ต้องแก้เว็บไซต์ แอป Script หรือระบบที่มีไฟล์หลายไฟล์ ได้ ถ้าไม่ได้ทำระบบ/โค้ด หรือกำลังทดลองในโฟลเดอร์ธรรมดา
Environment เครื่องมือที่ทำให้โปรเจกต์รันได้ เช่น Python, Node, Libraries, สิทธิ์เข้าถึง และ Network สำคัญเมื่อใช้ Codex Cloud เพราะเครื่อง Cloud ต้องรู้ว่าต้องเตรียมอะไรให้โปรเจกต์ ไม่ต้องสร้าง Cloud Environment ถ้าใช้ Chat/Work หรือใช้ Codex บนเครื่องตัวเอง
Plugin แพ็กเกจที่รวม Skill และ/หรือการเชื่อมเครื่องมือ เช่น MCP / Apps เมื่ออยากให้ AI ใช้วิธีทำงานเดิมและเรียกเครื่องมือเดิมซ้ำได้ ได้ เริ่มจาก Prompt + Project ก่อน แล้วค่อยทำ Plugin เมื่อ Workflow ลงตัว

Content / Slide Agent

เริ่มได้เลย

Project + Files + Instructions + Work

ไม่ต้อง Repo
ไม่ต้อง Environment
ไม่ต้อง Agents SDK

Website / Automation

เริ่มแตะ Codex

Folder/Repo + Codex

ถ้าใช้ My Computer ใช้ Environment บนเครื่อง
ถ้าใช้ Cloud ต้องเตรียม Cloud Environment

Agent Application จริง

ขั้นนักพัฒนา

Agents API หรือ Agents SDK + Tools + ระบบของบริษัท

จำเป็นเมื่อจะทำ Agent เป็น Product / App / Backend จริง ๆ เท่านั้น

5) Repo กับ Environment — ทำไมต้องมี และสร้างยังไง?

Repo = “แฟ้มงานของระบบ”

สมมติสร้างเว็บร้านค้า Repo คือโฟลเดอร์ที่มีไฟล์เว็บทั้งหมด เช่น หน้าเว็บ รูป Script และไฟล์ตั้งค่า พร้อมประวัติว่าใครแก้อะไรเมื่อไหร่

มันช่วยอะไร: Codex รู้ว่าของเดิมอยู่ตรงไหน แก้อะไรได้บ้าง และเราย้อน Version ได้

ไม่ทำได้ไหม: ได้ ถ้ายังทดลองงานเล็ก ๆ หรือใช้โฟลเดอร์ธรรมดา แต่ถ้าเริ่มเป็นระบบจริงควรใช้ Git/Repo

Environment = “โต๊ะทำงาน + เครื่องมือ”

ไฟล์อย่างเดียวรันไม่ได้ ถ้าไม่มีโปรแกรมและ Library ที่ต้องใช้ เช่น Python, Node.js, ffmpeg หรือสิทธิ์เชื่อม API

มันช่วยอะไร: ทำให้ Codex เปิดโปรเจกต์ Run, Test และแก้ระบบได้จริง

ไม่ทำได้ไหม: ถ้าใช้ My Computer เครื่องเรามี Environment อยู่แล้วบางส่วน แต่ถ้าใช้ Codex Cloud ต้องเตรียม Cloud Environment ให้พร้อมก่อนใช้งานซ้ำ

ตัวอย่างให้เห็นภาพ:
ไฟล์ Premiere/CapCut Project = คล้าย Repo
โปรแกรม CapCut + Codec + Font + Plugin ที่เครื่องต้องมี = คล้าย Environment
วิธีตัดคลิปของทีม = Skill

ถ้าจะใช้ Codex Cloud จากมือถือ ต้อง Setup ครั้งแรกแบบนี้

ทำบน Desktop หรือ Web ก่อน → เปิด Codex → เลือก Cloud → สร้าง/ตั้งค่า Environment
เลือก Project/Repository ที่ Codex จะทำงานด้วย ถ้าโปรเจกต์อยู่ GitHub ให้เชื่อม GitHub แล้วเลือก Repo
ให้ระบบเตรียม Dependencies เช่น npm install หรือ pip install -r requirements.txt ถ้าโปรเจกต์ต้องใช้
เพิ่มสิทธิ์ที่จำเป็น เช่น API credentials หรือ Network access เฉพาะบริการที่งานต้องใช้ — อย่าใส่รหัสลับไว้ใน Repo
Test Environment ให้โปรเจกต์เปิด/รัน/Test ได้จริง
Publish Environment เพื่อให้ใช้ Setup นี้ซ้ำกับ Task ใหม่ได้
จากนั้นเปิด มือถือ → Codex → Cloud → เลือก Environment → พิมพ์งาน งาน Cloud ทำต่อได้แม้คอมเราหลับ
ช่วยตรวจโปรเจกต์นี้เพื่อเตรียมใช้กับ Codex Cloud ทำตามลำดับ: 1. ตรวจว่าโปรเจกต์ใช้ภาษาและ framework อะไร 2. ตรวจว่าต้องติดตั้ง dependencies อะไรบ้าง 3. บอกคำสั่ง setup ที่ต้องใช้ 4. บอกว่าต้องใช้ environment variables / credentials อะไร โดยห้ามแสดง secret จริง 5. บอกว่า network ต้องอนุญาต domain ใดบ้าง 6. บอกวิธี test ว่า environment พร้อมแล้ว 7. สรุปเป็น checklist ก่อน Publish Environment ถ้าสิ่งไหนยังไม่จำเป็น อย่าเพิ่มเข้ามา

6) Codex: Cloud vs My Computer — เลือกจาก “งานอยู่ที่ไหน”

Cloud

Codex ทำงานบนเครื่องของ OpenAI

  • เหมาะเมื่ออยากสั่งจากมือถือแล้วปล่อยงานทำต่อ
  • คอมของเรา Sleep ได้ งาน Cloud ยังทำต่อ
  • ต้องมี Published Environment สำหรับโปรเจกต์นั้น
  • ถ้าทำกับระบบเดิม ควรมี Repo เพื่อเก็บ Source และ Version

My Computer

Codex ทำงานกับเครื่องจริงของเรา

  • เหมาะกับไฟล์ Local, Terminal และโปรแกรมที่ติดตั้งในเครื่อง
  • เริ่มง่ายกว่าเมื่อโปรเจกต์ยังอยู่ในโฟลเดอร์เครื่อง
  • ไม่ต้องสร้าง Cloud Environment ก่อน
  • แต่เครื่องต้องเปิดและออนไลน์ถ้าจะ Remote จากมือถือ
เลือกแบบนี้: ถ้างานต้องใช้ไฟล์/โปรแกรมใน Mac ตอนนี้ → My Computer
ถ้าอยากฝากงานไว้ให้ Codex ทำบน Cloud และคุมจากมือถือ → Cloud

7) AI Agent สร้างเองได้ 3 ระดับ — ไม่ต้องเริ่มจากโค้ดทุกคน

LEVEL 1 — Agent ใน ChatGPT

เหมาะกับ: Content, Slide, Research, Marketing

ใช้: Project + Files + Instructions + Work + Skill/Plugin

ไม่ต้องมี: Repo / Environment / API / SDK

นักเรียนทั่วไปควรเริ่มตรงนี้

LEVEL 2 — Agent ทำระบบด้วย Codex

เหมาะกับ: เว็บ, Automation, Script, Data Workflow, MCP

ใช้: Codex + Folder/Repo + Tools

Cloud: เพิ่ม Environment

ใช้เมื่อ Agent ต้องสร้างหรือแก้ระบบจริง

LEVEL 3 — Agent Application

เหมาะกับ: ทำ Agent เป็น Product, App หรือ Backend ของบริษัท

ทางง่ายกว่า: Agents API — OpenAI จัดการ Agent runtime ให้

ทางควบคุมมากกว่า: Agents SDK — เราคุม Tools, State, Approvals และ Deployment เอง

เป็นงานนักพัฒนา ไม่ใช่ขั้นบังคับสำหรับ Content/Slide Agent

ถ้าถามว่า “แล้วฉันควรเริ่มตรงไหน?”

โจทย์เริ่มตรงไหนRepo/Environment?
อยากมี Agent คิด Content ทุกวันProject + Work + Skillไม่ต้อง
อยากมี Agent ทำ Presentation จากข้อมูลWork + Google Slides/Canva Pluginไม่ต้อง
อยากให้ AI เตรียมไฟล์/Script เพื่อตัดคลิปWork + Codex My ComputerRepo ไม่บังคับ / Cloud Env ไม่ต้อง
อยากสร้างระบบอัตโนมัติที่รันบน Cloud และสั่งจากมือถือCodex CloudEnvironment ต้องมี / Repo แนะนำมาก
อยากสร้าง Agent เป็นแอปให้ลูกค้าใช้Agents API หรือ Agents SDKโดยทั่วไปต้องมีระบบโปรเจกต์และ Environment
Agent Builder: ไม่ควรใช้เป็นแกนหลักในการสอนตอนนี้ เพราะ OpenAI กำลังเลิกใช้ และกำหนดปิดวันที่ 30 พ.ย. 2026

8) ทดลองสร้าง Agent ไปพร้อมกัน — 3 Use Case

A. Content Agent — เริ่มที่ Chat/Work

ChatGPT → New Project → ตั้งชื่อ “Content Agent”
ใส่ Brand Guide / Persona / Product / ตัวอย่าง Content
เลือก Work ถ้าต้องการให้ทำหลายขั้นและส่งชิ้นงาน
วาง Prompt ด้านล่างแล้วทดสอบ
คุณคือ Content Planning Agent ของแบรนด์ [ชื่อแบรนด์] เป้าหมาย: สร้างคอนเทนต์ที่นำไปใช้ได้จริงและไม่ซ้ำกัน เมื่อฉันส่งหัวข้อหรือเป้าหมาย ให้ทำตามลำดับ: 1. อ่านข้อมูลแบรนด์และไฟล์อ้างอิงที่มี 2. ระบุ Audience และ Objective 3. สร้าง Hook 4. วาง Content Angle 5. เขียน Key Message 6. เลือก Format ที่เหมาะกับ Facebook / Instagram / TikTok 7. เขียน CTA 8. ระบุ KPI ที่ควรวัด 9. ตรวจซ้ำว่าไม่ขัดกับ Brand Guideline และไม่ซ้ำกับงานเดิม ส่งผลลัพธ์เป็นตารางสั้น กระชับ พร้อมใช้ทันที

B. Slide Agent — ใช้ Work

ChatGPT → Work
อัปโหลดเนื้อหา + Reference Deck/Template
ถ้ามี Canva/Google Slides Plugin ให้เชื่อมก่อน
วาง Prompt และให้ Work ทำ Deck ให้จบ
ทำหน้าที่เป็น Presentation Agent งาน: สร้าง Presentation จากไฟล์และข้อมูลที่แนบ กติกา: 1. สรุปสาระก่อนออกแบบ 2. หนึ่งสไลด์มีหนึ่ง Key Message 3. ตัดข้อความซ้ำและข้อความที่ไม่จำเป็น 4. ใช้โครงเรื่อง: Problem → Insight → Solution → Action 5. รักษา CI และ Template ที่แนบ 6. ใช้ตัวอักษรให้อ่านง่าย ไม่อัดข้อความ 7. สร้างชิ้นงาน Presentation ที่พร้อมนำเสนอ 8. ตรวจภาษา ตัวเลข และความสอดคล้องก่อนส่ง เริ่มทำจากข้อมูลที่แนบได้เลย

C. Video / CapCut Agent — ใช้แบบ Hybrid

ข้อเท็จจริง: ตอนนี้ไม่ควรสอนว่า “สร้าง Skill แล้ว ChatGPT จะคุม CapCut Desktop ได้ทันที” การควบคุมโดยตรงต้องมี Integration/API/MCP/Computer Control ที่รองรับก่อน

ให้ Chat/Work ทำ Script + Editing Brief + Caption
ถ้ามีไฟล์วิดีโอในเครื่อง ให้ Codex My Computer วิเคราะห์ไฟล์และเตรียมรายการตัด
เปิด CapCut Desktop → Project → Import clips
ไปที่ AI / Smart Edit → Auto Cut (ถ้าบัญชีมี) → เลือก Script Mode/ตัวเลือกที่รองรับ
นำ Brief/คำสั่งไปใช้ แล้วตรวจ Timeline ก่อน Export
ทำหน้าที่เป็น Video Editing Prep Agent โฟลเดอร์งาน: [ใส่ path] เป้าหมาย: ทำคลิปแนวตั้ง 9:16 ความยาว 30–45 วินาที สำหรับ Reels/TikTok ทำดังนี้: 1. ตรวจไฟล์ทั้งหมดในโฟลเดอร์ โดยห้ามแก้ต้นฉบับ 2. สรุปว่ามีคลิปอะไรบ้างและความยาวเท่าไร 3. เลือกช่วงที่ดีที่สุด พร้อม timestamp เข้า-ออก 4. เรียงลำดับ Hook → Main → Proof/Detail → CTA 5. สร้างไฟล์ edit_plan.md 6. สร้าง selects.csv ที่มี filename, in, out, reason 7. ถ้ามีเสียงพูด ให้สร้าง captions.srt 8. ระบุคำสั่งสั้น ๆ สำหรับนำไปใช้ต่อใน CapCut Auto Cut / Script Mode 9. ถ้าขาด dependency เช่น ffmpeg หรือ transcription tool ให้หยุดและบอกสิ่งที่ต้องติดตั้งก่อน ห้ามลบ ย้าย หรือ overwrite ไฟล์ต้นฉบับ
