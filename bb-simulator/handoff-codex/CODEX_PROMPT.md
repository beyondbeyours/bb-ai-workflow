คุณกำลังรับช่วงพัฒนา BB Simulator ต่อจาก Claude Code ใช้ไฟล์ในชุดนี้เป็นต้นทาง

อ่านก่อนเริ่มตามลำดับ:
1. START_HERE.md
2. HANDOFF_STATE.md (สถานะจริงของระบบ ไฟล์ ที่เก็บข้อมูล และข้อจำกัด)
3. RECOMMENDATIONS.md (งานที่ต้องทำต่อ เรียงตามความสำคัญ)
4. WORKLOG.md (ประวัติการแก้และเหตุผลทุกรอบ)
5. docs/original-handoff/MASTER_BRIEF.md, WORKFLOW_AND_INTEGRATIONS.md, REVIEW_AND_ACCEPTANCE.md

ตรวจซอร์สและเปิดเว็บจริงก่อนสรุป อย่าเชื่อเอกสารอย่างเดียว คำสั่งล่าสุดของแม่ใน WORKLOG.md มีลำดับสูงกว่าเอกสารเก่า

เป้าหมาย:
BB Simulator คือ Control Center สำหรับสั่งผลิต ติดตาม และตรวจงาน Content และ Video หลายแบรนด์ ใช้งานได้ทั้งมือถือและ laptop หน้าหลักคือเคบิน Private Jet ที่หมุนดูได้ BB อยู่ Cockpit ลูกทีมคือ Leo, Kitty, Tidy, Chicha แม่ต้องการลดการแก้งานหลายรอบให้น้อยที่สุด โดยให้สั่งงานได้ละเอียดเองตั้งแต่ต้น (Order Builder, Timeline ร่าง) และสั่งแก้เป็นจุดได้ตอนตรวจ (Review ปักหมุด)

ลำดับงาน:
1. ทำ P0 ใน RECOMMENDATIONS.md ให้ครบก่อน (เครื่องมือทดสอบ, state store, CSS, ทดสอบมือถือจริง, accessibility, ขนาดไฟล์, Cover Preview)
2. รันเทสต์เดิมทั้งหมดให้ผ่านก่อนและหลังแก้ทุกครั้ง และเพิ่มเทสต์ให้พฤติกรรมที่เปลี่ยน
3. งาน P1 ขึ้นไปที่ต้องใช้บัญชี สิทธิ์ หรือมีค่าใช้จ่าย ให้ตรวจ Documentation และราคาปัจจุบันจากแหล่งทางการ แล้วเสนอแม่พร้อมตัวเลือกที่แนะนำก่อนลงมือ ห้ามสร้างบัญชี ซื้อบริการ เปิด Automation โพสต์จริง หรือ Deploy ไปบัญชีใหม่เอง

กติกาที่ห้ามละเมิด:
- ห้ามทำปุ่มสำเร็จปลอมหรือสถานะเกินความสามารถจริงของระบบ Demo ต้องติดป้ายชัดเสมอ
- ห้ามเรียก MP4 หรือ media bundle ว่าโปรเจกต์ CapCut ที่แก้ไขได้
- ห้าม Export หรือโพสต์โดยไม่มีการอนุมัติของแม่ใน Canva/CapCut
- ข้อมูลแต่ละแบรนด์ห้ามปนกัน ชื่อแบรนด์ที่ถูกคือ Y&Z Stories (internal id ยังเป็น yaadz)
- รักษา key เดิม: ai-video-studio-briefs-v1, bb-simulator-draft-v1, IndexedDB bb-private-studio และ bb-simulator-review ถ้าเปลี่ยน schema ต้องมี migration และเทสต์
- ห้ามเปลี่ยนโลโก้ หน้าตา ทรงผม ชุดของตัวละคร และ CI (แดงไวน์ ขาว ชมพู เหลืองเล็กน้อย เคบินโทน ivory) ห้ามไอคอนหัวใจ กรอบซ้อนกรอบ ขอบเหลือง สีแดงสดแสบตา และไอคอนลูกเล่นเยอะจนรก
- English ใช้ Coolvetica แบบ Title Case, Thai ใช้ Kanit ตัวหนังสือต้องอ่านง่ายบนมือถือ
- ห้ามแต่ง Endpoint หรือ Capability ของ API ใดๆ
